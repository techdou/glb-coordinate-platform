# 通用 3D 坐标采集工具

这是一个浏览器版 3D 坐标采集工具：加载 GLB/GLTF 模型和名称列表，按名称逐个在模型上点选位置，最后导出 `{名称: [x, y, z]}`。

## 快速启动

Windows 双击：

```text
start.bat
```

PowerShell 启动：

```powershell
cd C:\Users\DouXiulu\Desktop\temp
.\start.ps1
```

指定端口：

```powershell
.\start.ps1 -Port 8010
```

不自动打开浏览器：

```powershell
.\start.ps1 -NoBrowser
```

启动后访问：

```text
http://localhost:8000/index.html
```

如果 8000 被占用，脚本会自动尝试后续端口，并在终端输出实际地址。

## 使用流程

1. 点击 `选择 GLB 模型`，加载 `.glb` 或 `.gltf`。
2. 点击 `导入 JSON 清单` 或 `粘贴名称列表`。
3. 在左侧列表点一个名称。
4. 在 3D 场景中点击对应位置，工具会记录 `[x,y,z]` 并自动选中下一个未采集名称。
5. 全部点完后点击 `导出坐标 JSON`。

导出的核心格式：

```json
{
  "预处理及进水在线监测用房": [-0.12, 0.03, 0.48],
  "水解酸化池": [0.21, 0.04, -0.35]
}
```

## 名称清单格式

支持一行一个名称：

```text
预处理及进水在线监测用房
水解酸化池
高效厌氧反应器及泥水分离系统
```

支持字符串数组：

```json
["预处理及进水在线监测用房", "水解酸化池"]
```

支持对象数组：

```json
[
  { "name": "预处理及进水在线监测用房" },
  { "name": "水解酸化池", "center": [0.1, 0.2, 0.3] }
]
```

支持完整工程格式：

```json
{
  "structures": [
    { "name": "预处理及进水在线监测用房", "center": [0.1, 0.2, 0.3] }
  ]
}
```

也支持名称到坐标的映射：

```json
{
  "预处理及进水在线监测用房": [0.1, 0.2, 0.3],
  "水解酸化池": null
}
```

## 稳健性说明

- 坐标导出为 GLB 模型局部坐标，不受页面居中显示影响。
- 鼠标拖动旋转不会误采点，只有短距离单击才记录坐标。
- 浏览器本地自动保存草稿，刷新后可以继续。
- 可以导入已有坐标继续补点。
- `导出坐标 JSON` 用于业务系统；`导出完整工程` 用于下次继续编辑。

## 坐标是否通用

坐标不具有跨模型的绝对普适性。它绑定的是同一个 GLB 的局部坐标系，也就是模型的原点、缩放、朝向和几何内容必须一致。

通常仍然有效的情况：

- 同一个 GLB 文件重新打开。
- 只做 Draco 压缩，且没有改变模型原点、缩放、旋转和几何位置。
- 同一个模型在业务系统中按相同坐标系加载。

可能失效的情况：

- 重新导出 GLB 时改了原点、缩放、旋转或整体位置。
- 换了模型版本，构筑物几何位置发生变化。
- 旧版工具导出的坐标被当成新版局部坐标导入。

本项目早期工具记录的是“模型被页面居中之后的场景坐标”，新版工具记录的是“GLB 原始局部坐标”。如果导入早期工具打的点后位置跑偏，请先加载同一个 GLB，然后点击 `迁移旧版坐标`，再用 `浏览模式` 抽查几个点是否回到对应构筑物。

`迁移旧版坐标` 不能自动判断你的 JSON 一定来自旧版工具。迁移前会保存一份浏览器本地备份；如果抽查发现位置不对，点击 `撤销迁移` 恢复。

## 常见问题

**为什么不能直接双击 `index.html`？**

浏览器会限制本地文件读取，导致 JSON、GLB 或 Three.js 模块加载失败。用 `start.ps1` 启动本地 HTTP 服务即可。

**为什么要人工采点？**

当前 GLB 已合并为单个 mesh，模型内部没有可靠的构筑物名称节点，无法自动从模型里拆出 19 个构筑物。人工点选是这个数据条件下最稳的方式。
