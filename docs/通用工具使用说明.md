# 通用 3D 坐标采集工具 · 使用说明

本文档详细说明工具的通用工作流、功能按钮、文件格式与坐标约束。

## 一、定位

这是一个**通用**的 3D 坐标采集工具——不绑定任何特定模型或案例。打开页面就是空白工作台：

- **模型**：你提供的任意 `.glb` / `.gltf` / `.stl` 文件。
- **名称清单**：你提供的名称列表（5 种格式，见下文）。`app/examples/ljw/structures.json` 提供了一份精简清单样例，可直接导入参考格式。

## 二、启动

| 平台 | 方式 |
| --- | --- |
| Windows | 双击 `start.bat` |
| macOS / Linux | 终端运行 `./start.sh` |
| 任意平台 | `python scripts/start.py` |

启动脚本（`scripts/start.py`）会：

1. 自动从 8000 端口起找一个空闲端口（被占用则递增）。
2. 在 `app/` 目录启动本地静态服务器（支持 HTTP Range，大模型加载更稳）。
3. 自动打开默认浏览器到 `http://localhost:<端口>/index.html`。

命令行参数：

```text
-p, --port N        起始端口（默认 8000）
--host ADDR         监听地址（默认 127.0.0.1；0.0.0.0 开放局域网）
--no-browser        不自动打开浏览器
```

> 不能直接双击 `index.html`：浏览器会限制本地文件读取，导致 JSON/GLB/JS 模块加载失败。必须用本地 HTTP 服务打开。

## 三、核心工作流

### 1. 加载模型

- 点 **选择 GLB / STL 模型** 选文件，**或**直接把 `.glb` / `.stl` 文件拖进 3D 窗口。
- 模型会自动居中显示，相机自动适配。

### 2. 准备名称清单

任选一种方式：

- **导入 JSON 清单**：选择一个 `.json` 文件。
- **粘贴名称列表**：打开对话框，一行一个名称粘贴（也支持粘贴 JSON）。

> 没有现成清单？可参考 `app/examples/ljw/structures.json` 的格式，把它直接拖入窗口或点「导入 JSON 清单」加载，看看效果。

### 3. 采点（采集模式）

1. 在左侧列表点一个名称（高亮为当前选中）。
2. 在 3D 模型对应位置**单击**一次（注意：拖动旋转视角不会误采点，只有短距离单击才记录）。
3. 工具记录该名称的 `[x, y, z]`，自动跳到下一个未采集名称。
4. 全部点完后，列表无高亮，提示可导出。

### 4. 浏览校验（浏览模式）

切到**浏览模式**，点任意已采集名称，相机会飞到对应坐标，方便抽查。

视角快捷按钮（右下角）：
- **Fit** 适配模型整体
- **Top** 俯视
- **Iso** 斜视

## 四、名称清单格式

| 格式 | 示例 |
| --- | --- |
| 一行一个名称（纯文本） | `预处理及进水在线监测用房<br>水解酸化池` |
| 字符串数组（JSON） | `["点位A", "点位B"]` |
| 对象数组（JSON） | `[{"name":"点位A"},{"name":"点位B","center":[1,2,3]}]` |
| 完整工程（JSON） | `{"structures":[{"name":"点位A","center":[1,2,3]}]}` |
| 名称→坐标映射（JSON） | `{"点位A":[1,2,3],"点位B":null}` |

粘贴纯文本时，行首的序号（如 `1.` `2)` `1-`）会被自动去掉。

## 五、导出

| 按钮 | 用途 | 格式 |
| --- | --- | --- |
| **导出坐标 JSON** | 给业务系统用 | `{名称: [x,y,z]}`，未采集为 `null` |
| **导出完整工程** | 下次继续编辑 | 含模型 SHA-256、包围盒、坐标系说明、点位 |
| **导出草稿** | 备份进度到文件 | 含清单 + 坐标，换设备可恢复（模型需另行提供） |
| **导入草稿** | 从文件恢复进度 | 读取草稿 JSON，刷新页面生效 |

> 工具会自动把进度存到浏览器 localStorage。但 localStorage 仅限当前浏览器，**清缓存或换浏览器会丢失**——重要进度请用「导出草稿」存成文件。

## 六、坐标约束

采集的坐标是 **模型局部坐标**（GLB/GLTF/STL 通用，不是页面显示坐标），不受居中显示影响。

**仍然有效：**
- 同一个 GLB 文件重新打开。
- 只做 Draco 压缩，且没改变原点/缩放/旋转/几何位置。
- 业务系统按相同坐标系加载该模型。

**可能失效：**
- 重新导出 GLB 时改了原点、缩放、旋转或整体位置。
- 换了模型版本，构筑物几何位置变化。
- 把旧版工具的「居中场景坐标」当成新版「局部坐标」用。

## 七、迁移旧版坐标

早期工具记录的是「模型被页面居中之后的场景坐标」，新版记录「GLB 原始局部坐标」。若导入旧版坐标后位置跑偏：

1. 加载**同一个** GLB 模型。
2. 点 **迁移旧版坐标**（会先保存一份撤销备份）。
3. 切到**浏览模式**抽查几个点。
4. 若位置不对，点 **撤销迁移** 恢复。

> 工具不能自动判断你的 JSON 是否一定来自旧版，请用浏览模式目视确认。

## 八、草稿数据结构

导出的草稿 JSON 结构：

```json
{
  "type": "generic-3d-coordinate-collector-draft",
  "schemaVersion": "1.0.0",
  "exportedAt": "2026-06-29T...",
  "storageKey": "generic_coordinate_collector_v1",
  "draft": {
    "structures": [ { "name": "...", "center": [x,y,z], "status": "已采集" } ],
    "activeIndex": 0,
    "modelLabel": "model.glb",
    "migrationBackup": null,
    "savedAt": "..."
  }
}
```

## 九、模型压缩

103MB 级别的大模型加载较慢，可用压缩脚本生成 DRACO + 纹理优化的压缩版：

```bash
python scripts/compress_model.py
python scripts/compress_model.py 输入.glb 输出.glb --quality medium
```

质量档位：
- `high`：高保真，体积缩减较少
- `medium`（默认）：平衡，约减 70%
- `low`：高压缩，约减 80%，细节有损

需 Node.js（首次自动下载 gltf-transform）。压缩后的 GLB 体积更小、加载更快，可在界面里点「选择 GLB 模型」自行导入使用。

## 十、故障排查

| 现象 | 原因与解决 |
| --- | --- |
| 打开白屏 | 没用本地服务器，直接双击了 HTML。用 `start.py` 启动。 |
| 模型加载失败 | 文件不是有效的 GLB/GLTF/STL；或 GLB 用了 DRACO 压缩但解码器异常（已内置，离线可用）。STL 仅支持二进制和 ASCII 两种标准格式。 |
| 点不上坐标 | 处于浏览模式（切回采集模式）；或没点中模型表面（靠近目标再点）。 |
| 端口被占 | 启动脚本会自动换端口，看终端输出的实际地址。 |
| 草稿丢失 | localStorage 仅限当前浏览器。重要进度用「导出草稿」。 |
